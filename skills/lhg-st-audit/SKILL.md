# lhg-st-audit：谈判准备自查方法论

> 目标：上桌前最后一道门，确保"该想的都想了、该练的都练了"。
> 核心纪律：**blocker 不清零不许上桌；为清零改规则算作弊。**

## 1. 何时使用

- 策略 + 话术 + 演练全部做完 → 上桌前跑全流程
- 只想快速看一眼准备度 → 只跑第 3.1 步（脚本），10 秒出结果
- 谈判后复盘 → 用第 3.4 节沉淀

## 2. 输入与输出

**输入**：`谈判准备.md` + `话术稿.md` + `演练复盘表.md`。

**输出**：`自查报告-YYYYMMDD.md`（审计结果 + 人工复核 + 底线清单），结论"通过 / 不通过"。

## 3. 分步方法论

### 3.1 跑确定性审计脚本（必做，零 LLM 成本）

在准备文档目录执行插件自带的两个脚本：

```
python3 <插件目录>/scripts/audit/prep_audit.py   --target <准备文档目录>
python3 <插件目录>/scripts/audit/script_audit.py --target <准备文档目录>
```

- blocker：缺 BATNA、缺底线、缺开价锚点、缺让步阶梯、过早暴露底线、威胁式语言——必须清零
- warning：缺备选筹码、缺异议应对、市场数据无来源标注、开价无依据、让步无交换、收尾无书面确认、情绪化表述——修掉或写豁免理由
- 有 blocker 时脚本非零退出，供提交前 hook 拦截用

### 3.2 分级处理

1. blocker 逐条修，修一条跑一遍对应脚本确认消失
2. 修不掉的（如 BATNA 实在没有）→ 列入"需人工处理"，并调整策略（BATNA 弱就改打"价值牌"，不要硬装强硬）
3. warning 修掉或写豁免理由 + 有效期（如"本次先谈 base，筹码下轮再谈"）
4. **不许**为了清零而删规则或改脚本阈值

### 3.3 人工复核（脚本做不到的）

1. **数字复核**：三点定位的三个数字重新算一遍——开价依据还在吗？底线是算出来的还是拍脑袋的？
2. **话术试读**：把话术稿读出声，凡是"说不出口"的句子全部改写（拗口的话术上桌一定崩）
3. **底线默写**：合上文档，默写出底线数字和让步阶梯——上桌时没人给你看稿，记不住等于没准备
4. **最坏情况**：问自己"如果对方今天只给底线价，我走还是留？"——提前做决定，上桌不纠结

### 3.4 底线清单（自查通过后输出，随身带）

```markdown
# 底线清单（谈判当天随身）
- 开价：__k（依据：__）
- 目标：__k
- 底线：__k（到线即停，转"我考虑一下"）
- 让步阶梯：__→__（换__）→__（换__）→停
- 必争筹码：__
- 绝不说的三句话：①我的底线是__ ②我最低接受__ ③不给就走
- 对方联系人/电话：__
- 我的 deadline：__（与 BATNA 挂钩）
```

这张清单是上桌前看最后一眼的东西，一页纸，不许多。

### 3.5 谈判后复盘（24 小时内）

1. 对方实际开了多少？和你预判的差多少？
2. 哪次让步让早了？哪次交换换亏了？
3. 对方哪句话是虚招（"预算卡死"后来松了）？记下来，下次识破
4. 最终结果 vs 目标：达标/超标/未达标，原因是什么？
5. 更新你的"市场数据"：这次谈到的数字就是下次的依据（脱敏后）

### 3.6 审计分级处置流程（文字版）

```
跑脚本
  ├─ blocker > 0 → 逐条修 → 复跑确认 → 还有？→ 列入"需人工处理"并调策略
  ├─ warning > 0 → 修掉，或写豁免（理由+有效期）→ 进报告
  └─ 只有 nit → 顺手修
人工复核（四项：数字重算/话术试读/底线默写/最坏情况）
  └─ 任一项不过 → 回到对应 skill 返工，不许带病上桌
输出底线清单 → 结论"通过" → 上桌
```

**记住**：审计是"门"不是"流程"。门的作用是拦住没准备好的人，不是走个过场。

### 3.7 谈判档案管理（一家公司一档）

```
谈判档案-XX科技/
├── 谈判准备.md      # 策略（冻结版，标日期）
├── 话术稿.md        # 话术（演练修订版）
├── 演练复盘表.md    # 每轮复盘
├── 自查报告-YYYYMMDD.md
├── 底线清单.md      # 上桌随身的一页纸
└── 书面offer.pdf    # 谈定后归档
```

多家公司并行时，一家一档，数字不许串（A 公司的开价不要记成 B 公司的）。档案保留到入职后 3 个月——试用期薪资争议时，这是你的证据。

### 3.8 豁免的写法规范

warning 可以豁免，但豁免必须书面化，格式如下：

```markdown
## 豁免清单
- [PREP-005] 缺备选筹码 → 豁免。理由：对方是初创公司，明确无股票期权，
  筹码战场不存在。有效期：本次谈判。下轮谈判重新评估。
- [TALK-005] 收尾无书面确认 → 不豁免，已补。
```

**豁免三原则**：①只豁免 warning，blocker 不许豁免；②理由必须具体（"时间不够"不算理由）；③写有效期，到期复查。口头豁免等于没豁免。
**豁免复查**：下次谈判前，把上次的豁免清单翻出来逐条问"这次还成立吗"——过期的豁免自动失效。

## 4. 反模式

- ❌ 自查只跑脚本不做人工复核——脚本查不出"底线是拍脑袋的"
- ❌ 底线清单写两页纸——上桌前看不完的等于没有
- ❌ 谈判后不复盘——同样的坑下次还踩
- ❌ 把自查报告发给对方——这是你的作战地图，不是给对方看的
- ❌ 一次谈判用两套策略——演练定下来的，上桌不要改

## 5. 自检与反馈

1. 两个脚本是否都跑了且 blocker 清零？→ 没跑不算做
2. 数字复核是否重算了一遍？→ 没算不算
3. 底线能否默写？→ 默写不出就继续背
4. 底线清单是否一页纸？→ 超了就删
5. 豁免清单是否书面化？→ 口头豁免等于没豁免

标准冒烟用例：对插件自带的 `fixtures/` 跑脚本，确认坏 fixture 的 blocker 全命中、好 fixture 零 blocker（见仓库根 `smoke_test.py`）。
